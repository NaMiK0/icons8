# Спецификация: генератор лендингов из выгрузки Google Search Console

Документ фиксирует контракты, по которым написан код. Если реализация
расходится со спецификацией, сначала правится спецификация, потом код.

Источник требований: тестовое задание Icons8, SEO Developer.

---

## 1. Задача и границы

**На входе:** выгрузка запросов из Google Search Console по icons8.com (`.csv` или `.zip`).
**На выходе:** ~10 самодостаточных HTML-лендингов, связанных между собой, хаб-страница
и машинный отчёт о каждом принятом решении.

**Обязательное свойство:** скрипт отрабатывает на другой выгрузке из той же консоли без
правки кода. Всё, что может меняться, вынесено из кода:

| что | где |
|---|---|
| бренд, продукты, рынок, описание каталога, пороги, число страниц, модели, переключатели | `config/config.toml` |
| тексты промптов | `config/prompts/*.md` |
| адрес API, ключ, подмена основной модели на один запуск | `.env` |

**Вне рамок:** деплой, реальные ассеты каталога, `sitemap.xml`, дизайн.

---

## 2. Стадии пайплайна

```
выгрузка
  → [ingest]      чтение файла                       → list[Query]
  → [normalize]   склейка дублей, усечение по лимиту  → list[Query]
  → [filters]     правила: бренд, язык, мусор, порог  → list[Decision]
  → [classify]    модель: чужой бренд, интент         → list[Decision]
  → [group]       лексические группы                  → list[LexicalGroup]
  → [cluster]     модель: группы → ~10 кластеров      → list[Cluster]
  → [content]     модель: текст страницы              → PageContent на кластер
  → [accounting]  учёт каждой строки выгрузки         → list[Decision]
  → [render]      HTML                                → out/*.html
  → [report]      отчёт                               → out/report.json, out/excluded.csv
```

Стадии с моделью — `classify`, `cluster`, `content`. У каждой есть путь без модели
(§16), и каждый переход на него виден в `report.warnings`.

## 3. Модели данных (`domain/models.py`)

```python
Intent = Literal["transactional", "informational", "navigational"]

@dataclass(frozen=True)
class Query:
    raw: str                  # строка из выгрузки без изменений
    text: str                 # нижний регистр, свёрнутые пробелы
    clicks: int
    impressions: int
    ctr: float                # доля 0..1
    position: float | None    # None, если в выгрузке нет или 0

@dataclass
class Decision:               # решение по одному запросу
    query: Query
    keep: bool
    reason: Reason
    note: str
    source: Literal["rule", "llm", "default", "flag"]   # кто решил
    intent: Intent | None

@dataclass
class LexicalGroup:           # запросы с одинаковой лексической подписью
    key: str
    queries: list[Query]      # canonical — запрос с максимумом кликов

@dataclass
class MergedDuplicate:        # след склейки дублей
    kept: str
    absorbed: Query

@dataclass
class Cluster:                # одна будущая страница
    slug: str
    primary_keyword: str
    groups: list[LexicalGroup]
    intent: Intent
    source: Literal["llm", "lexical"]
    rationale: str
    content: PageContent | None

@dataclass
class PageContent:
    title: str; meta_description: str; h1: str; intro: str
    sections: list[Section]   # heading + paragraphs
    faq: list[FaqItem]        # question + answer
    anchor_text: str
    source: Literal["llm", "template"]
```

Метрики групп и кластеров (`clicks`, `impressions`, `avg_position` с весом показов,
`potential`) — вычисляемые свойства, не поля.

## 4. Причины исключения (`domain/reasons.py`)

Перечень **закрытый**: это значения колонки `reason` в `excluded.csv` и ключи сводки
в `report.json`. Каждая строка выгрузки получает ровно одну причину или попадает на страницу.

| reason | кто назначает | когда |
|---|---|---|
| `own_brand` | правило | свой бренд в любом написании или название собственного продукта |
| `non_english` | правило | нелатинский алфавит или слово из `market.non_english_markers` |
| `irrelevant` | правило / модель | пустой запрос, адрес сайта; к каталогу не относится |
| `low_volume` | правило | показов меньше `input.min_impressions` (по умолчанию правило выключено) |
| `third_party_brand` | модель / офлайн-маркер | чужая торговая марка или связанный с ней символ |
| `not_a_landing_intent` | модель / офлайн-маркер | блог, инструкция, новость, взлом софта |
| `duplicate` | учёт | склеен с другим написанием того же запроса, метрики сложены |
| `truncated` | учёт | за пределами топ-`max_queries` по потенциалу |
| `unclustered` | учёт | прошёл фильтры, но не попал в набор страниц |

`own_brand` и `third_party_brand` отменяются переключателями `keep_brand` и
`keep_third_party` (§15): запрос остаётся, `source="flag"`.

## 5. Потенциал роста (`domain/scoring.py`)

Страницы ранжируются по тому, сколько можно выиграть, а не по текущим кликам.

```
opportunity(position) = clamp((position − 3) / 7, 0, 1)   # 0 в топ-3, 1 с позиции 10
opportunity(None)     = 0.5                                # позиции в выгрузке нет
potential(query)      = impressions × opportunity(position)
potential(cluster)    = Σ potential(query)
```

Сортировка кластеров: `potential` ↓, `impressions` ↓, `clicks` ↓, `slug` ↑ — последний
ключ делает порядок детерминированным.

## 6. Чтение выгрузки (`ingest/`)

- Вход — `.csv` или `.zip`. Из архива берётся csv, в имени которого есть `quer`
  (консоль кладёт рядом `Pages.csv`, `Countries.csv`), иначе первый csv.
- Кодировки по очереди: `utf-8-sig`, `utf-8`, `cp1251`, `latin-1`.
- Разделитель — `csv.Sniffer` среди `, ; \t |`, при неудаче — самый частый символ.
- Заголовки сравниваются после нормализации (регистр, скобки, `%`, диакритика) со
  словарём синонимов `ingest/headers.py`: `query` / `Top queries` / `Запрос` /
  `Популярные запросы` и т. д. Сначала точное совпадение, затем вхождение.
- Порядок колонок произвольный, лишние игнорируются. Обязательна только колонка запроса;
  нет метрики — нули и предупреждение; нет CTR — вычисляется из кликов и показов.

**Числа разбираются по типу колонки** (`ingest/numbers.py`):

| | клики, показы | CTR, позиция |
|---|---|---|
| `26,306` / `26 306` / `26.306` | тысячи → 26306 | — |
| `0.083` | — | десятичная → 0.083 |
| `0,5495` | — | десятичная → 0.5495 |
| `54.95%` / `54,95%` | — | процент → 0.5495 |
| есть `.` и `,` | правый разделитель — десятичный | то же |

Без разделения по типу CTR `0.083` читался бы как 83. CTR больше 1 считается процентом.
Позиция 0 — `None`. Пустые значения, `-`, `n/a` — 0; нераспознанное — 0 и предупреждение.

Колонки запроса нет — `InputError` со списком найденных заголовков, код выхода 1.
Загрузчик ничего не отбрасывает.

## 7. Нормализация (`pipeline/normalize.py`)

**Дедуп:** запросы, совпадающие после нормализации, склеиваются: клики и показы
суммируются, позиция усредняется с весом показов, CTR пересчитывается.

**Усечение:** после дедупа остаются топ-`max_queries` по потенциалу.

**Лексическая подпись группы:** нижний регистр → только `[a-z0-9]` → стоп-слова
(`for`, `the`, `best`, `online`, `com`…) → единственное число → сортировка → через `-`.
`free icons download` и `download free icons` дают одну подпись.

**Опечатки:** подпись длиной от 6 символов, отличающаяся от существующей на одну
правку, присоединяется к ней: `custom curser` → группа `custom cursor`.

## 8. Правила (`pipeline/filters.py`)

1. **Мусор** — пустой, короче 2 символов, адрес сайта → `irrelevant`.
2. **Свой бренд** — запрос без пробелов и пунктуации содержит алиас из `brand.aliases`
   или отличается от него на `brand.fuzzy_distance` правок → `own_brand`.
   Срабатывает **только если в запросе есть цифра**: иначе `icons` (15 257 кликов)
   отличался бы от `icons8` на одну букву.
3. **Собственные продукты** — слово или фраза из `brand.products` целиком, без нечёткого
   поиска → `own_brand`.
4. **Язык** — символы вне латиницы или слово из `market.non_english_markers` → `non_english`.
5. **Порог** — показов меньше `input.min_impressions` → `low_volume`.
6. **Офлайн-маркеры** `[offline]` → `third_party_brand` / `not_a_landing_intent`.
   Применяются **только если модель не используется или не ответила** — иначе чужие
   бренды решает она.

## 9. Классификация (`pipeline/classify.py`)

**Модели:** `[models] classify`, по умолчанию Flash → 27B. Промпт — `config/prompts/classify.md`.

- В модель уходят только запросы, по которым правила не приняли решение `own_brand` или
  `non_english`: эти причины проверяемы механически и остаются за правилами.
- Пачки по `llm.batch_size` (50). Строка пачки: `номер. запрос | clicks | impressions | position`.
- Ответ — `{"items": [{"id", "keep", "reason", "intent", "note"}]}`. Сопоставление **по
  номеру строки**: модель копирует в ответ строку целиком вместе с метриками, по тексту
  сопоставление ломается. Текст — запасной способ.
- Починка ответа: `reason` вне перечня → `irrelevant` (или `ok` при `keep=true`);
  `keep=true` → `reason=ok`; `keep=false, reason=ok` → `irrelevant`.
- Нет решения по запросу → остаётся решение правил + предупреждение.
- Пачка не удалась → для неё решения правил, остальные пачки не теряются.
  Не удались все → вся классификация уходит на правила с офлайн-маркерами.
- **Варианты написания:** запрос, помеченный моделью как `third_party_brand`, но
  отличающийся от оставленного запроса на одну правку по подписи, возвращается
  (`freeicon` = `free icon` без пробела).

## 10. Кластеризация (`pipeline/llm_cluster.py`, фолбэк `pipeline/cluster.py`)

**Модели:** `[models] cluster`, по умолчанию 27B → Flash. Промпт — `config/prompts/cluster.md`.

В модель уходят **лексические группы, а не запросы**: подпись, главный запрос, до 5
запросов, клики, показы, средняя позиция, потенциал. Ответ —
`{"clusters": [{"primary_keyword", "slug", "intent", "group_keys", "rationale"}]}`.

После ответа всё детерминированно:

1. Несуществующие ключи групп пропускаются, повтор группы во втором кластере игнорируется.
2. Забытые группы присоединяются к кластеру с наибольшим пересечением слов, при нуле —
   становятся отдельным кластером.
3. **Слишком широкие кластеры делятся.** Если кластеров меньше `target − tolerance`,
   делится самый крупный, **но только если он больше средней страницы**
   (`групп > max(2, всего групп / target)`). Иначе деление разобрало бы как раз то
   объединение по смыслу, ради которого вызывалась модель.
4. Сортировка по §5; берутся до `target` кластеров от `min_queries_per_cluster`
   запросов. Мелкие добираются, только если крупных меньше `target − tolerance`.
   Всё, что не вошло, — `unclustered`.
5. Slug: `[^a-z0-9]+` → `-`, до 60 символов по границе слова, коллизия → `-2`, `-3`.

**Без модели** группы сливаются вокруг затравок — самых весомых групп — по общим
неочевидным словам (слово, встречающееся больше чем в 30 % групп, — «icon» — очевидное).
Сравнение с затравкой, а не с накопленным набором слов: иначе кластеры сцепляются цепочкой.

## 11. Тексты (`pipeline/llm_content.py`, фолбэк `pipeline/content.py`)

**Модели:** `[models] content`, по умолчанию 27B → Flash. Промпт — `config/prompts/content.md`.
Один вызов на страницу; в модель уходят ключевое слово, интент, до 15 запросов с
метриками, названия соседних страниц.

Ответ проверяется теми же функциями, что ограничивают шаблон:

- `title` > 60 или `meta_description` > 155 символов → обрезка по границе слова без
  висящих союзов и знаков + предупреждение;
- секций меньше 3 или вопросов меньше 4 → добор из шаблона + предупреждение;
  вопросов больше 6 → лишние отбрасываются;
- числа из 3+ цифр → предупреждение (вероятный выдуманный факт);
- предложения о лицензиях, регистрации, оплате, составе каталога → целиком в
  предупреждения: у модели нет данных каталога, и пробелы она заполняет догадками.

Промпт запрещает выдуманные факты, описание возможностей каталога, инструкции по ОС и
чужие бренды. Запрет снижает частоту, но не гарантирует отсутствия — поэтому детекторы.

**Шаблон:** H1 из ключевого слова, секции и FAQ из запросов кластера по фиксированным
формулировкам. Структура полная, текст очевидно шаблонный.

## 12. Страницы (`render/`)

Один файл на страницу, ноль внешних запросов: CSS в `<style>`, превью — инлайн-SVG,
ссылки относительные, открывается по `file://`. Перед записью старые `*.html` в
каталоге удаляются.

Лендинг:

- `<!doctype html>`, `lang`, `charset`, `viewport`;
- `<title>`, `description`, `canonical` (`site.base_url` + slug), `og:*`;
- хлебные крошки `<nav aria-label="Breadcrumb">`;
- ровно один `<h1>`, вводный абзац;
- сетка из 8 инлайн-SVG с `role="img"`, `<title>`, `aria-label` — заглушки, реальных
  ассетов у скрипта нет;
- 3–4 `<section>` с `<h2>`; FAQ: `<h2>` + `<h3>` на вопрос;
- таблица «Searches covered by this page» — **только при `show_search_metrics`**;
- `<nav>` «Related pages» — ссылки на все остальные страницы keyword-анкорами;
- один `<script type="application/ld+json">` с `@graph`: `WebPage`, `BreadcrumbList`, `FAQPage`;
- футер: исходный файл, дата, источник кластеров и текстов.

Хаб `index.html`: `<h1>`, таблица страниц; метрики и сводка исключений — только при
`show_search_metrics`; JSON-LD `CollectionPage`.

## 13. Отчёт (`reporting/`)

`out/excluded.csv` — каждый не попавший на страницы запрос, по убыванию кликов:
`query, clicks, impressions, ctr, position, reason, reason_label, note, decided_by`.

`out/report.json`:

```
generated_at
input      path, encoding, delimiter, columns_found, columns_missing, rows_read,
           rows_skipped, duplicates_merged, truncated, queries, clicks, impressions, potential
mode       llm, clustering, content, models{classify,cluster,content}, keep_brand,
           keep_third_party, show_metrics, config
filters    kept, dropped, kept_clicks, dropped_clicks, kept_potential, dropped_potential,
           by_reason{reason: queries, clicks, potential, label, examples}
clusters   slug, primary_keyword, intent, file, source, content_source, title, queries,
           clicks, impressions, avg_position, potential
llm_usage  stage, model, calls, cache_hits, input_tokens, output_tokens, reasoning_tokens, seconds
warnings   каждая деградация, починка и подозрительное место
```

Клики склеенных дублей в итоги `dropped_*` не входят — они уже в запросе, с которым склеены.
`report.json` — источник цифр для README.

**Инвариант учёта:** строк выгрузки = запросов на страницах + строк `excluded.csv`.
Нарушение — предупреждение в отчёте.

## 14. Клиент модели (`llm/`)

- OpenAI-совместимый `POST {LLM_BASE_URL}/chat/completions` на стандартной библиотеке:
  так говорят proxyAPI, OpenRouter, Ollama. Сертификаты — `certifi`, если установлен.
- `response_format: json_object`, не strict `json_schema`: на проверке строгая схема
  давала валидный, но заметно худший по смыслу ответ.
- `temperature` и `reasoning_effort` — из `[llm]`. Температура 0 уменьшает разброс, но
  не убирает: между прогонами модель меняет часть решений.
- Повторы с паузой 2^n с на сетевых ошибках, 408/409/429/5xx — до `llm.max_retries`.
- Негодный ответ (не JSON, не объект, не прошёл проверку стадии) — до 3 попыток с
  указанием на ошибку; негодные ответы не кэшируются.
- **Цепочка моделей:** модель не ответила после всех попыток или вернула ошибку,
  которую повторять бессмысленно, — запрос уходит следующей. Переход пишется в предупреждения.
- **Кэш** `.cache/llm/<sha256(payload)>.json`: повтор на тех же данных бесплатен и даёт
  те же страницы. **Кэш отдаётся и без ключа** — прогон на `data/gsc_queries.csv`
  воспроизводит `out/` у того, у кого ключа нет. Кэш лежит в репозитории.
- Расход токенов — по стадии и модели в `report.llm_usage`.

## 15. Запуск (`cli/options.py`)

```
python run.py --input PATH [--out DIR] [--config PATH]
              [--max-queries N] [--target-pages N] [--tolerance N]
              [--llm | --no-llm] [--cache | --no-cache]
              [--keep-brand | --no-keep-brand] [--keep-third-party | --no-keep-third-party]
              [--metrics | --no-metrics] [--log-level LEVEL]
```

Приоритет: **флаг > `config.toml` > дефолт в коде**. Переключатели живут в `[run]` и
`[render]` конфига с описанием `true`/`false`; парный флаг меняет значение на один запуск
в любую сторону.

| переключатель | по умолчанию | флаги |
|---|---|---|
| `run.use_llm` | `true` | `--llm` / `--no-llm` |
| `run.use_cache` | `true` | `--cache` / `--no-cache` |
| `run.keep_brand` | `false` | `--keep-brand` / `--no-keep-brand` |
| `run.keep_third_party` | `false` | `--keep-third-party` / `--no-keep-third-party` |
| `render.show_search_metrics` | `true` | `--metrics` / `--no-metrics` |

`.env`: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL_CLASSIFY/CLUSTER/CONTENT` (заменяют
основную модель стадии, запасные остаются), `LLM_REASONING_EFFORT`. Ключ — только в
окружении, в конфиг и репозиторий не попадает.

Коды выхода: `0` — успех; `1` — выгрузку или конфиг не прочитать; `2` — после фильтров
не осталось запросов или не собралось ни одного кластера.

## 16. Деградация вместо падения

| ситуация | поведение |
|---|---|
| нет ключа | ответы из кэша; где их нет — правила и шаблоны |
| `--no-llm` | модель не вызывается; правила с офлайн-маркерами, лексика, шаблоны |
| основная модель не ответила | следующая модель цепочки |
| не ответила ни одна модель | путь без модели для этой стадии |
| пачка классификации не удалась | для неё решения правил, остальные пачки сохраняются |
| модель забыла группы, придумала ключи | группы пристраиваются по общим словам |
| модель собрала одну страницу «про всё» | кластер крупнее средней страницы делится |
| в тексте не хватает секций или вопросов | добор из шаблона |
| выгрузка без метрик | нули, ранжирование по алфавиту, предупреждение |
| большая выгрузка | топ-`max_queries` по потенциалу, остальное `truncated` |
| данных меньше, чем на `target` страниц | столько, сколько есть, с предупреждением |

Любая деградация видна в `report.warnings`.

## 17. Приёмка

1. `python run.py --input data/gsc_queries.csv` → `out/index.html`, ~10 лендингов,
   `report.json`, `excluded.csv`; код выхода 0.
2. Страницы открываются по `file://`, внешних запросов нет, перелинковка в обе стороны.
3. `python -m unittest discover -s tests -t .` — зелёный, сеть не используется.
4. Незнакомые выгрузки отрабатывают без правки кода: zip из интерфейса консоли,
   русский интерфейс с `;` и запятыми, 20 строк, 3000 строк, только брендовые запросы
   (код 2).
5. Учёт: строк выгрузки = на страницах + в `excluded.csv`, на каждой выгрузке.
6. Без ключа прогон на `data/gsc_queries.csv` воспроизводит `out/` побайтно.
7. `--no-llm` даёт полный набор страниц.
8. На каждой странице один H1, валидный JSON-LD, title ≤ 60, description ≤ 155; ни в
   одном заголовке нет брендовых и чужих запросов.
