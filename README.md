# Лендинги из выгрузки Google Search Console

Скрипт берёт выгрузку поисковых запросов по icons8.com и собирает около десяти
связанных между собой лендингов: решает, какие запросы заслуживают страницы,
объединяет их в кластеры по потребности, пишет текст и собирает самодостаточные
HTML-файлы. Каждое решение — что вошло на страницу, что отброшено и почему —
записывается в отчёт.

Результат прогона на `data/gsc_queries.csv` лежит в [`out/`](out/): хаб
[`index.html`](out/index.html), 10 лендингов, [`excluded.csv`](out/excluded.csv)
со всеми отброшенными запросами и [`report.json`](out/report.json). Контракты
всех стадий — в [`SPEC.md`](SPEC.md).

## Как запустить

Нужен Python 3.11 или новее.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python run.py --input data/gsc_queries.csv
```

Результат появится в `out/`; открыть `out/index.html` в браузере. Страницы
открываются двойным кликом: стили внутри файла, картинок и шрифтов извне нет.
Превью ассетов на страницах — заглушки из геометрических фигур: доступа к
каталогу Icons8 у скрипта нет.

**Ключ API.** Ключ proxyAPI передан вместе со ссылкой на репозиторий — его нужно
вписать в `.env` в строку `LLM_API_KEY=`. В репозитории ключа нет и быть не
должно. Без ключа скрипт тоже работает: на `data/gsc_queries.csv` ответы модели
берутся из кэша, который лежит в репозитории (`.cache/llm/`), и получаются те же
страницы с теми же текстами, что в `out/`. На новой выгрузке без ключа модель заменяется
правилами и шаблонами — страницы собираются, но тексты у них шаблонные.

**Своя выгрузка.** `--input` принимает csv или zip прямо в том виде, в каком его
отдаёт консоль, из английского или русского интерфейса, с любым разделителем и
форматом чисел — править код не нужно:

```bash
.venv/bin/python run.py --input ~/Downloads/icons8.com-Performance-on-Search.zip --out result
```

Проверено на выгрузках, которых скрипт не видел: zip из интерфейса консоли с
`Top queries` и CTR в процентах, русский интерфейс с `;` и запятыми в числах,
выгрузка на 20 строк, на 3000 строк и выгрузка из одних брендовых запросов
(скрипт честно завершается с кодом 2: страниц делать не из чего).

**Время и деньги.** Первый прогон на 100 запросах — около трёх минут и около
2 ₽: классификация 0.20 ₽, кластеризация 0.25 ₽, тексты 1.65 ₽. Повторный прогон
на тех же данных занимает секунды и ничего не стоит — ответы берутся из кэша.

**Переключатели.** Постоянные значения — в `config/config.toml`, разделы `[run]` и
`[render]`, у каждого написано, что делают `true` и `false`. Флаг меняет значение
на один запуск:

| что | по умолчанию | флаги |
|---|---|---|
| работать через модель | да | `--no-llm` / `--llm` |
| брать ответы модели из кэша | да | `--no-cache` / `--cache` |
| оставлять запросы своего бренда | нет | `--keep-brand` / `--no-keep-brand` |
| оставлять чужие торговые марки | нет | `--keep-third-party` / `--no-keep-third-party` |
| показывать на страницах клики, показы и позиции | да | `--no-metrics` / `--metrics` |

Метрики включены, чтобы при проверке было видно, из каких запросов собрана
каждая страница; перед публикацией их выключают — свои клики и позиции наружу не
показывают. Объём задают `--target-pages`, `--tolerance` и `--max-queries`;
полный список — `run.py --help`.

**Что меняется без кода.** Бренд и названия продуктов, что считается каталогом,
пороги, число страниц, модели и их запасные — в `config/config.toml`. Тексты
промптов — в `config/prompts/*.md`.

**Тесты.** `.venv/bin/python -m unittest discover -s tests -t .` — 202 теста, сеть
не используется: модель подменяется заглушкой, которая отвечает так, как
отвечает живая, — забывает группы, возвращает `null`, пишет слишком длинные
заголовки.

## Как устроено

```
выгрузка → чтение → склейка дублей → правила → модель: отбросить или оставить
         → группы по словам → модель: группы в кластеры → модель: текст страницы
         → учёт каждого запроса → HTML → отчёт
```

Модель вызывается в трёх местах, где нужно суждение: чужой ли это бренд,
какие запросы — одна потребность, как написать страницу. Всё остальное делает
обычный код, потому что он предсказуем, бесплатен и покрыт тестами.

Страницы ранжируются не по кликам, а по **потенциалу роста**: показы, умноженные
на расстояние до топ-3. Запрос, по которому сайт уже на первом месте, новой
страницей не улучшить, поэтому его потенциал — ноль. `icons8` с 26 тысячами
кликов оказывается внизу списка, а `custom cursor` с 300 тысячами показов на
пятой позиции — наверху.

Каждая строка выгрузки попадает в одно из двух мест: на страницу или в
`excluded.csv` с причиной. Скрипт проверяет это в каждом прогоне: на выгрузке из
3000 строк раньше бесследно терялось 2811 запросов, отсеянных вне фильтров.

## Какую модель выбрали и почему

Модели — Qwen3.5 через proxyAPI: **Flash** для классификации и **27B** для
кластеризации и текстов. Клиент говорит на OpenAI-совместимом протоколе, поэтому
провайдер не зашит: proxyAPI, OpenRouter, локальная Ollama и сам OpenAI
подключаются тремя строками в `.env`. Сменить модель на Claude или GPT — одна
строка.

Разделение по стадиям выбрано по замеру, а не по интуиции. Классификация — это
раскладка запросов по закрытому списку причин, суждения там мало. Я прогнал её на
обеих моделях: они совпали в 13 решениях из 14, и у каждой была одна ошибка —
Flash сочла `freeicon` чужим брендом, 27B отбросила `custom cursor for android`.
При равном качестве Flash в четыре раза дешевле (0.20 ₽ против 0.78 ₽ за стадию)
и в пять раз быстрее. Кластеризация и тексты требуют суждения и приличного
английского, там стоит 27B.

Ещё три решения тоже приняты по замеру. **Рассуждения выключены**: с ними
классификация шла 301 секунду вместо 51 и стоила вдвое дороже, а решения не стали
лучше. **Ответ запрашивается свободным JSON, а не строгой схемой**: со строгой
схемой модель отвечала формально валидно, но по смыслу хуже — оставила `shein`, а
`free icons` дала причину «не лендинг». **Температура 0**, но это не делает ответы
повторяемыми: на одних и тех же данных модель между прогонами меняет часть
пограничных решений. Повторяемость обеспечивает кэш, поэтому он лежит в
репозитории.

Модели не доверено ничего, что код может проверить сам. Её ответы
сопоставляются по номеру строки, а не по тексту, потому что она копирует в ответ
строку целиком вместе с метриками. Литерал `null` вместо ответа (у 27B это
случается при температуре 0) переспрашивается до трёх раз. Забытые группы
пристраиваются по общим словам. Страница «про всё» делится — в одном прогоне
модель сложила в кластер `icons` 21 группу из 43. Для остатков у модели есть
явная корзина: без неё она собирала страницу-свалку вроде «gun emoji плюс icon
download плюс cursors». Если основная модель не отвечает, запрос уходит
запасной, а если не отвечает ни одна — стадия переходит на правила и шаблоны.
Каждый такой переход виден в предупреждениях отчёта.

Слабое место — тексты. 27B пишет приличный английский, но заполняет пробелы
догадками: в первых версиях были «встроенный редактор курсоров в macOS» (его не
существует) и «для бесплатной версии нужна атрибуция» (условий лицензии модель
не знает). Промпт это подавляет, но не устраняет, поэтому фразы про лицензии,
доступ, оплату и состав каталога, а также числа из трёх и больше цифр выносятся в
предупреждения отчёта для проверки человеком. Более сильная модель снизит частоту
таких фраз, но не уберёт её: у модели нет данных каталога. Первое, что я бы сделал
с бюджетом, — прогнал тексты через Claude Sonnet и сравнил; второе описано в
последнем разделе.

## Какие запросы отброшены и почему

Из 100 запросов на страницы попали 60, отброшено 40. Каждый отброшенный лежит в
[`out/excluded.csv`](out/excluded.csv) с причиной, комментарием и тем, кто принял
решение: правило или модель.

| причина | запросов | кликов | потенциал | примеры |
|---|---:|---:|---:|---|
| свой бренд | 12 | 42 938 | 112 | icons8, icon8, icons 8, 8icons, icon8. com |
| не вошли в набор страниц | 11 | 4 310 | 17 068 | gun emoji, custom icons, icon pack |
| не лендинг каталога | 9 | 9 921 | 12 574 | icon maker, tiktok blue tick injector, graphic design trends 2027 |
| чужая торговая марка | 7 | 15 053 | 130 985 | instagram logo, apple logo copy, shein, phonepe |
| не английский | 1 | 89 | 0 | kursor myszki do pobrania |

**Свой бренд — 12 запросов, 43 тысячи кликов и потенциал 112.** Это главная цифра
раздела. По брендовым запросам сайт уже на позициях 1.0–2.9 (у одного — 4.0), CTR
до 84%: человек ищет Icons8 и находит Icons8. Новая страница сюда ничего не
добавит, только отберёт трафик у существующих. Правило ловит все написания, в том
числе `icon8. com` и `8 icon`, одним нечётким сравнением, но только в запросах с
цифрой: без этого `icons` — самый ценный общий запрос выгрузки, 15 тысяч кликов —
отличался бы от `icons8` на одну букву и был бы отброшен.

**Чужие торговые марки — 7 запросов.** `instagram logo`, `apple logo copy`,
`shein`, `shazam`, `phonepe`, синие галочки и значки верификации. Здесь отказ не
бесплатен, и это стоит сказать прямо: 83% потерянного потенциала — это
`instagram logo`, 173 тысячи показов на седьмой позиции. Лендинг под чужую марку
в заголовке — юридическое решение, а не SEO, поэтому по умолчанию такие запросы
отбрасываются; `--keep-third-party` возвращает их одной строкой. По «синим
галочкам» при этом сайт и так на первом месте с CTR 50–60% — страница там не
нужна при любом решении. Список чужих брендов не захардкожен: на незнакомой
выгрузке будут другие марки, поэтому решает модель.

**Не лендинг каталога — 9 запросов.** Три вида. Инструменты: `icon maker`,
`icon creator`, `faceswapper`, `icon finder` — человек хочет сделать иконку или
найти сервис, а не скачать ассет. Взлом софта: `tiktok blue tick injector`,
`fake blue tick emoji copy and paste`. Тема для блога: `graphic design trends
2027`. Граница «что считается каталогом» задана одной фразой в
`config/config.toml` — `a catalog of design assets: icons, illustrations and 3D
graphics`. Поменять охват, например добавить инструменты, — поменять фразу.

**Не вошли в набор страниц — 11 запросов.** Они прошли фильтры, но на десяти
страницах им не нашлось места: `gun emoji` с потенциалом 671 (сайт уже на третьей
позиции), `icon pack`, `icons for ppt`, `mac icons` и другие мелкие группы, у
которых нет пары для полноценной страницы. Страницу из одного запроса скрипт
берёт, только если широкие кластеры делить больше нечего.

**Не английский — 1 запрос**, `kursor myszki do pobrania`: рынок англоязычный.

**Что не отброшено, хотя выглядит мусором.** Опечатки и варианты написания —
это тот же спрос, записанный неточно: `custom curser` склеен с `custom cursor`,
`free icon` и `icons free` — с `free icons`. `freeicon`
модель сочла брендом конкурента, но правило вернуло его: запрос, отличающийся от
оставленного на одну правку, чужой маркой быть не может.

Решения модели по пограничным запросам меняются между прогонами: в одном прогоне
`icon maker` оставался, в другом — отброшен как инструмент. Поэтому цифры выше —
из закоммиченного прогона, и он воспроизводится из кэша.

## Что сломается, если лендингов нужно 5000

Ломается в трёх местах принципиально — это не лечится ускорением, — и в
нескольких механически.

### Принципиально

**Скрипт не знает, что у Icons8 уже есть миллион страниц.** Он генерирует
страницу под `free icons`, не проверяя, что такая страница у сайта наверняка уже
есть и ранжируется. На десяти страницах для демонстрации это терпимо, на 5000 —
массовая каннибализация: новые страницы конкурируют со старыми за те же запросы,
и проседают обе. Решение: консоль отдаёт запросы вместе со страницами, по которым
они показываются. Для каждого кластера смотрим, какой URL сайта уже ранжируется;
есть в топ-10 — результат не «новый лендинг», а «доработать эту страницу». Новая
страница создаётся только там, где ни один URL не закрывает потребность. Из 5000
кандидатов реально новых может оказаться в разы меньше, и это правильный
результат.

**Кластеризация одним запросом к модели.** Сейчас все группы уходят в модель
одним списком. На 40 группах уже видно всё, что она делает не так: забывает от
одной до четырёх групп за прогон, собирает страницу «про всё», устраивает свалку
из остатков. Для 5000 страниц нужно порядка 30–50 тысяч запросов и 15–20 тысяч
групп — такой список не поместится в запрос, а качество развалится гораздо
раньше. Решение: группировать алгоритмом, а не моделью. Лучший сигнал для SEO —
пересечение выдачи: запросы, у которых совпадают три и больше URL в топ-10 Google,
относятся к одной странице — так кластеризует сам поисковик. Дешевле — эмбеддинги
и HDBSCAN. Модели остаётся маленькая задача на каждый кластер: назвать и
проверить, что внутри одна потребность. Это тысячи коротких независимых вызовов
вместо одного огромного.

**Текст модели без данных каталога.** Детектор уже сейчас находит на страницах
фразы про лицензии и доступ, которых модель не может знать. Десять страниц можно
вычитать руками, 5000 — нет. Хуже того, 5000 сгенерированных страниц без
уникальных данных — это то, что Google называет scaled content abuse: политика
против массовых страниц, сделанных ради ранжирования, а не ради пользы, и она
действует независимо от того, кто писал текст. Под неё можно потерять не новые
страницы, а доверие ко всему домену. Решение: страница стоит на реальных данных
каталога — сами иконки кластера, их число, стили, форматы, превью из базы
Icons8. Модель пишет только связующий текст, и эти же данные подаются ей в
промпт — выдумывать становится нечего. Проверка автоматическая, человек смотрит
только страницы, помеченные детектором, и случайную выборку.

### Механически

- **Вход.** Интерфейс консоли выгружает не больше 1000 строк — на 5000 страниц
  этого не хватит. Нужна загрузка через Search Console API постранично.
- **Время.** Текст одной страницы — 10–17 секунд, последовательно 5000 страниц —
  14–24 часа. Деньги не проблема: около 0.17 ₽ за страницу, порядка 1000 ₽ за весь
  набор. Решается параллельными запросами с учётом лимитов провайдера или
  batch-API, который дешевле и отдаёт результат пачкой.
- **Перелинковка.** Сейчас каждая страница ссылается на все остальные — на 5000
  это 4999 ссылок. Нужна иерархия: хабы по категориям и 5–10 ближайших страниц.
- **Стабильность адресов.** Модель на одних данных решает немного по-разному, а
  рендер перед каждым прогоном удаляет старые файлы. За время работы над заданием
  набор страниц менялся несколько раз. Для живого сайта смена URL — потеря
  позиций. Нужен реестр «кластер → адрес»: опубликованная страница обновляется, а
  не пересоздаётся.
- **Публикация.** Вместо папки с HTML — выгрузка в CMS и sitemap, и выпуск
  волнами, а не 5000 страниц в один день: с замером по консоли, какие страницы
  начали получать показы, и снятием тех, что не взлетели.

### Что уже готово к масштабу

Загрузчик прочитал 3000 строк за 0.4 секунды и переживает любой формат выгрузки.
Учёт гарантирует, что ни один запрос не пропадёт молча на любом объёме. Кэш даёт
возобновляемость: если прогон упадёт на трёхтысячной странице, перезапуск не
потратит ни токена на первые две тысячи девятьсот девяносто девять. Сбой одной
пачки или одной модели не валит прогон. Ответы модели чинятся детерминированным
кодом, а не надеждой на промпт — на тысячах вызовов эта разница решает.
